# i18n Coverage Plan — 2026-05-19

## Problem

InkyCap's i18n seam (`src/lib/i18n.ts`, `t()` + `src/locales/en.json`) exists
but is barely used: ~50 keys, ~11 files calling `t()`, while ~80 source files
hardcode user-facing English directly. Estimated **~350–500 genuine
user-facing strings** to migrate (the same string — e.g. the six sort modes —
is also duplicated across panels, which is what surfaced this review).

Goal: route all user-facing text through a single source, and design the seam
so InkyCap can ship **alternate-language versions** later. Enforce it so it
does not re-rot.

## Locked decisions

- **Seam:** adopt a best-practice, locale-switchable design (not the current
  stub). Real multi-language is a stated future goal.
- **Enforcement:** AST-based ESLint rule (+ grep CI backstop) blocks new
  hardcoded strings; a dev-only **pseudo-locale** verifies migration
  completeness.
- **Rust:** `InkyCapError` gains stable machine-readable codes; the frontend
  maps codes → `errors.*` translation keys.

## Two structural problems behind the symptom

1. **Option arrays store resolved strings.** `LINKS_SORT_OPTIONS` holds
   `label: "Name (A to Z)"`. Fix is structural: option arrays store a
   **`labelKey`**, and the *render site* calls the translator. Shared
   vocabulary (name/modified/created × asc/desc) gets shared keys, not
   per-panel copies.
2. **No enforcement.** Nothing stops the next component hardcoding text.

## Seam design (Phase 0)

- Adopt **`@solid-primitives/i18n`** — Solid-official, narrow, reactive
  (satisfies CLAUDE.md "narrow over kitchen-sink"; rejected `solid-i18next`
  as a heavier i18next wrapper). Vet the dependency + transitives on add.
- **Dual-face seam**, one dictionary behind both:
  - *Reactive translator* for Solid components — re-renders on locale change.
  - *Static `t()` snapshot* for non-component code (CM6 editor extensions in
    `src/editor/**`, `src/lib/commands.ts`, stores). A runtime locale change
    triggers an editor reconfigure to pick up new strings — rare, acceptable.
- **Plurals:** `t(key, { count })` selects `.one` / `.other` / … sub-keys via
  the built-in `Intl.PluralRules` (zero dependency). Replaces today's manual
  `references.entry` / `references.entries` pair.
- **Formatting:** numbers/dates via `Intl.NumberFormat` / `Intl.DateTimeFormat`,
  never hand-formatted.
- **Locale files:** one JSON per locale (`en.json`, future `fr.json`, …);
  keep flat dotted keys. Locale selection is a persisted setting.
- **Conventions doc:** namespace by *feature area* not component
  (`sort.*`, `search.*`, `settings.editor.*`); shared vocab → shared keys.
  Document in `i18n.ts` header + a CLAUDE.md section.

## Phases

**Phase 0 — Seam foundation.** Implement the dual-face seam above, plural +
format helpers, locale-switch setting, conventions doc.

**Phase 1 — Shared vocabulary.** Extract cross-cutting keys first: six sort
modes, common buttons (Add/Delete/Cancel/Browse/Reset), common placeholders
(Filter…), generic toasts. Migrate option arrays (`LINKS_SORT_OPTIONS` and
siblings) to the `labelKey` pattern. Resolves the original duplication.

**Phase 2 — Enforcement.** AST-based ESLint rule flagging hardcoded literals
in JSX text + `title=`/`placeholder=`/`aria-label=`/`alt=`; genuine
exceptions get an inline annotation (precedent: `// utf8-safe:`). Grep-style
CI test as blunt backstop (precedent: `src-tauri/tests/utf8_safety.rs`).
Generate a `en-XX` pseudo-locale (bracketed/lengthened strings) for dev sweeps.
Start lint at "warn".

**Phase 3 — Bulk migration, one area per pass** (each independently
reviewable + testable):
1. Settings — `SettingsPanel.tsx`, `CreationRuleEditor.tsx` (~120 strings)
2. Collection config — `CollectionTable.tsx` (~60)
3. Sidebars & panels — `LeftSidebar.tsx`, `RightPanel.tsx`,
   `MycelialView.tsx`, `TemplatesPanel.tsx`
4. Editor UI — `selection-toolbar.ts`, `command-palette.ts`
5. Commands & dialogs — `commands.ts`, `ExportDialog.tsx`, `NoteComposer.tsx`
6. Toasts & confirms — scattered (~40)

**Phase 4 — Rust error codes.** Give each `InkyCapError` variant a stable
code; serialize `{ code, params }` to the frontend; frontend maps code →
`errors.<code>` key with params. (`src-tauri/src/errors.rs`.)

**Phase 5 — Cleanup.** Promote lint warn→error per migrated path. Pseudo-locale
completeness sweep. Remove dead manual-plural keys.

## Out of scope / notes

- Rust has no native menus, dialogs, or templates — only `InkyCapError` and
  the `"InkyCap"` brand name. No general Rust-side i18n needed beyond Phase 4.
- Actually authoring non-English translations is a follow-up; this plan
  delivers the capability and full `en` coverage.
